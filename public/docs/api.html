API & intégration

Agent BI expose une API REST classique pour les actions ponctuelles, et un flux Server-Sent Events pour la console live. Tout passe par un token JWT (Authorization: Bearer <token>).

Authentification

POST /api/auth/register

{
  "email": "alice@example.com",
  "password": "…"
}

Crée un compte. Retour : 201 + {user_id, email}.

POST /api/auth/login

{
  "email": "alice@example.com",
  "password": "…"
}

Retourne un JWT signé (HS256) : {"access_token": "eyJ…", "token_type": "bearer", "expires_in": 86400}.

Le token porte les claims sub, iss=agent-bi, exp, roles. Toute requête au-delà de login/register exige l'en-tête Authorization.

Pipeline

POST /api/upload

Multipart form-data ; champ file. Retour : { "upload_id": "...", "kind": "xlsx" | "csv" }.

POST /api/start

{
  "source_type": "upload" | "sqlserver",
  "upload_id": "uuid",              // si upload
  "sql": { "host": "...", "db": "..." }, // si sgbd
  "options": { "target": "star", "enable_scd2": true }
}

Retour immédiat : {"session_id": "uuid", "status": "started"}. Le pipeline s'exécute en tâche de fond ; la progression est diffusée via SSE.

GET /api/pipeline-stream?session=…

Flux text/event-stream. Exemples d'événements :

event: log
data: {"level":"info","step":"ingestion","message":"12 400 lignes chargées"}

event: progress
data: {"percent": 32, "step": "modeling"}

event: done
data: {"success": true, "star_schema": {...}}
Reconnexion sûre. Si le client se déconnecte puis revient, les messages manqués sont rejoués depuis le buffer serveur (deque par session, capacité 500).

Requête en langage naturel

POST /api/query

{
  "session_id": "uuid",
  "question": "Top 5 produits par marge en 2025"
}

Retour :

{
  "sql": "SELECT p.Nom, SUM(f.Marge) AS m FROM Fact_Ventes f …",
  "rows": [ {"Nom": "Produit A", "m": 128430}, … ],
  "chart": { "type": "bar", "x": "Nom", "y": "m" }
}

Exports

POST /api/export/{format}

format ∈ pdf | pptx | html | xlsx | powerbi. Corps :

{
  "session_id": "uuid",
  "include": ["schema", "kpis", "top-queries"]
}

Retour : {"url": "/files/exports/abc123.pdf"}. Les fichiers sont signés et expirent au bout de 24 h.

Santé & versions

GET /api/health
→ {"status": "ok", "uptime_s": 124356, "version": "1.0.0"}

GET /api/version
→ {"agent_bi": "1.0.0", "llm": "claude-sonnet-4-5"}

Codes d'erreur

CodeSignificationAction
401JWT absent / expiréRafraîchir via login
403Rôle insuffisantDemander un rôle plus élevé
404Session inconnueLancer un nouveau pipeline
409Conflit (pipeline déjà en cours)Attendre ou annuler
429Rate limitBackoff exponentiel
502LLM indisponibleRéessayer ; fallback auto côté serveur

Webhooks (optionnel)

Pour intégrer Agent BI à un ordonnanceur externe, configurez WEBHOOK_URL dans .env. À la fin de chaque pipeline, une requête POST est envoyée avec le payload {session_id, success, duration_ms, star_schema_hash}, signée HMAC-SHA256 via WEBHOOK_SECRET.

Clients officiels

  • JavaScript : @agent-bi/client — wrap fetch + EventSource, gestion automatique du JWT.
  • Python : agent_bi_client — basé sur httpx et sseclient.
import { AgentBI } from "@agent-bi/client";
const client = new AgentBI({ token });
const session = await client.start({ upload_id });
client.onLog(session.id, (e) => console.log(e));
await client.done(session.id);
