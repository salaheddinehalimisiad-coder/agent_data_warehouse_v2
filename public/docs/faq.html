Questions fréquentes

Les réponses aux interrogations les plus courantes sur Agent BI — usage, limites, extensions.

Usage général

Puis-je connecter d'autres SGBD que SQL Server ?

Oui à la lecture (MySQL, PostgreSQL, Oracle, Snowflake) : l'agent Ingestion utilise SQLAlchemy pour lire presque toutes les sources JDBC/ODBC. En revanche, le chargement du warehouse cible par défaut SQL Server car la couche DDL utilise T-SQL (MERGE, SCD Type 2). Un adaptateur PostgreSQL est prévu dans la roadmap.

Quelle taille de fichier est supportée ?

Les tests passent jusqu'à 2 Go d'Excel ou 10 Go de CSV sur une machine à 16 Go de RAM. Au-delà, il est préférable de passer par le connecteur SGBD pour éviter les lectures en mémoire.

Quelle langue comprend l'agent NL→SQL ?

Français, anglais et arabe par défaut. D'autres langues sont possibles en ajustant le prompt système, mais les résultats sont meilleurs en français et anglais (corpus d'entraînement plus riche sur le SQL).

Modélisation

Le modeleur peut-il générer un snowflake et pas seulement une étoile ?

Oui, via l'option model_style: "snowflake" du payload /api/start. Le mode par défaut reste l'étoile car il offre les meilleures performances analytiques pour 90 % des cas.

Et les dimensions lentement changeantes (SCD) ?

L'option enable_scd2: true active le type 2 sur les dimensions détectées comme historisables (par ex. adresse client). La DDL injecte ValidFrom, ValidTo, IsCurrent et le chargeur gère l'historisation via MERGE.

Comment exclure une colonne sensible ?

Dans la vue Schémas, ouvrez une table, cliquez sur la colonne puis Exclure. L'exclusion est persistée dans la config du pipeline et sera appliquée automatiquement à la prochaine exécution.

LLM & coûts

Combien coûte un pipeline ?

En moyenne, 0,12 USD pour un dataset de 100 k lignes / 20 colonnes, tous agents compris. Les coûts sont dominés par le modeleur et l'analyste. Un cache de prompts réduit de 30 % le coût des runs répétés sur une même source.

Puis-je utiliser un autre LLM ?

Oui. Le wrapper llm_client.py est abstrait ; une implémentation OpenAI GPT-4 et une implémentation locale (Ollama + Llama 3) sont disponibles dans la branche expérimentale. Attention : la qualité des décisions de modélisation est supérieure avec Claude Sonnet 4.5 dans nos évaluations.

Performance

Pourquoi le pipeline semble-t-il "attendre" entre les étapes ?

Les étapes cognitives (profileur, modeleur, analyste) appellent le LLM — la latence est incompressible (2 à 8 s par appel). Le chargeur, lui, est limité par SQL Server. Surveillez la console live : chaque étape publie sa durée, vous saurez immédiatement où se situe le goulet.

Comment accélérer les chargements ?

  • Activer bulk_insert: true (utilise BCP sous le capot) dans /api/start.
  • Créer des index columnstore sur les tables de faits.
  • Partitionner les faits par année / mois pour les très gros volumes.

Dépannage

La console reste vide après Lancer.

Ouvrez la devtools (onglet Network) et vérifiez /api/pipeline-stream : statut 200 attendu. Si 401, le JWT a expiré (reconnectez-vous). Si 404, le backend n'a pas démarré ou l'URL du proxy est mauvaise.

Erreur "ODBC Driver not found".

Installez le driver Microsoft ODBC 18 for SQL Server (documentation Microsoft). Sur Debian/Ubuntu : 

curl https://packages.microsoft.com/keys/microsoft.asc | sudo apt-key add -
curl https://packages.microsoft.com/config/ubuntu/22.04/prod.list | sudo tee /etc/apt/sources.list.d/mssql-release.list
sudo apt update
sudo ACCEPT_EULA=Y apt install -y msodbcsql18

Comment réinitialiser un pipeline bloqué ?

Rechargez la page (la session SSE sera refermée). Côté serveur, la tâche en cours est annulée au bout de 10 min d'inactivité ; vous pouvez aussi appeler POST /api/cancel?session=….

Contribution

Comment proposer un nouvel agent ?

Fork, créez un dossier api/agents/monagent/ avec agent.py, prompt.txt, tests/. Ajoutez-le au graphe dans api/agents/__init__.py. Ouvrez une PR : notre CI lance les évaluations automatiques.

Où signaler un bug ?

Sur GitHub, avec un minimum d'informations : version, source utilisée, logs SSE (console navigateur), et étapes de reproduction. Les traces côté serveur se trouvent dans api/logs/agentbi.log.
